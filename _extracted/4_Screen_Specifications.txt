Part 1
Frontend Overview

1. Frontend overview
The frontend is a single Next.js application (App Router) serving three portals from one codebase. All screens are web-only and responsive down to tablet width for kiosks. No mobile app.
1.1 The three portals
Portal
Route prefix
Who uses it
Auth
Admin
/admin/*

Email + password + TOTP
Member self-service
/me/*
Self-registered users
Email + OTP
Kiosk
/kiosk, /register, /enroll
Shared terminals, new registrants
Device token / none

1.2 Tech & component rules
Framework: Next.js 14 App Router, React, TypeScript.
Styling: Tailwind CSS with shadcn/ui as the base component library.
Data: TanStack Query for server state; tables via TanStack Table; charts via Recharts.
Camera: navigator.mediaDevices.getUserMedia; capture a frame to canvas, convert to base64 JPEG.
No localStorage tokens: auth is cookie-based. Never store the session in JS-accessible storage.
All forms send the X-CSRF-Token header on submit.

Part 3
Key Screens In Detail

3. Key screens in detail
The most important and complex screens are specified here. The rest follow the same pattern: a list/table screen, a create/edit form, or a detail view.
K1 — Kiosk check-in
Purpose: The always-on terminal screen. Captures faces continuously and records attendance.
Components:
Full-screen live camera view with a face-positioning ring.
Status text: 'Look at the camera' → 'Scanning' → result.
Result card: name, role, score, check-in/out badge, time.
Device + zone label in a corner; today's event count.
API calls:
POST /faces/search with the captured frame + device_id + action=auto.
Device authenticates via its device-token cookie.
States to handle:
Idle (waiting for a face).
Scanning (frame sent, awaiting response).
Match — check-in (green).
Match — check-out (amber, shows duration).
No match (red, 'not registered').
Blacklist hit (red alert, 'do not admit').
Quality fail (ask to retry).
Auto-reset to idle after 3.5 seconds.

K4 — Consent + face capture
Purpose: Collects DPDP consent then captures the face. Used in self-registration and guardian enrollment.
Components:
Four mandatory consent checkboxes (purpose, sensitivity, rights, free consent).
Confirm button — disabled until all four are ticked.
Camera box, enabled only after consent.
'Use manual attendance instead' alternative, always visible.
API calls:
POST /consent (before capture).
POST /faces/enroll (after capture).
States to handle:
Consent incomplete (button disabled).
Camera off / on / captured.
Quality pass → proceed.
Quality fail → retry message.
Success → confirmation screen with consent ref.

A2 — Dashboard overview
Purpose: The admin's home. Live metrics, live feed, recent registrations, device status.
Components:
Four metric cards: checked-in, inside now, late, absent.
Live check-in feed (auto-refresh).
Recent registrations list.
Device status panel.
Tab nav to attendance / users / alerts.
API calls:
GET /attendance/presence (metrics + inside).
GET /attendance?from=today (feed).
GET /users?sort=created (recent).
GET /devices (status).
States to handle:
Loading skeletons per panel.
Empty (no data yet).
Live update (poll every 10s).
Alert badge count on the Alerts tab.

A7 — Admin-assisted enrollment
Purpose: Admin enrolls a patient/inmate/citizen/devotee/visitor/guardian on their behalf.
Components:
Person-type selector (6 types).
Details form (fields change by type).
Four admin-confirmation checkboxes.
Camera capture.
Optional consent-form file upload.
Success card with enrollment + consent refs.
API calls:
POST /admin/enroll (multipart: details + image).
States to handle:
Type not selected.
Form incomplete.
Confirmations unticked (capture disabled).
Capture success/fail.
Enrolled — option to enroll another.

M6 — Request erasure
Purpose: Lets a member exercise their DPDP right to erasure.
Components:
Explanation of what erasure does and does not delete.
OTP re-authentication step.
Confirm button with a clear warning.
Result: erasure reference + downloadable certificate.
API calls:
POST /me/data/erasure (after OTP re-auth).
States to handle:
Pre-confirmation explainer.
OTP challenge.
Processing (cascade running).
Complete — show certificate link.
Switched to manual attendance notice.
